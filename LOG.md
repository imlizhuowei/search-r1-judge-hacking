## Notes & Issues

- 2026-11-04: Retriever died with `Segmentation fault (core dumped)` (not OOM: container RAM ~20 GB after, no OOM in dmesg). Cause: FastAPI runs the sync endpoint in a thread pool, so concurrent tool calls ran torch encode + faiss search in several threads at once; torch and faiss each ship an OpenMP runtime, a known crash combo. Fix: `retriever/batcher.py` — one worker thread owns torch+faiss, merges requests arriving within 5 ms (<=256 queries) into one batched search (also faster for a flat index); `launch.sh` restarts the server if it exits. Tested: 40 concurrent clients -> single thread, merged batches, correct routing.
- 2026-11-04: GRPO+EM baseline (grpo_em_s1, 64x5, 300 steps) ran ~00:30–11:00; train reward 0.087 -> ~0.20 by step 203, 1.6–2.6 min/step, response length rose 279 -> 474 around step 170–200 (to inspect). GCA smoke then failed: `AssertionError: GCA needs gca/reward.py ...` because this verl reads `reward.custom_reward_function.*`; the top-level `custom_reward_function.*` we passed is silently ignored by the reward loop (only fully_async migrates it), so the default EM reward ran without our labels. Fixed in smoke_train.sh/train.sh. Also saw the retriever refuse connections during the GCA smoke (retriever had to be restarted at its start too) -> cause unknown yet (suspect container OOM; check mem.log/dmesg). Reduced CPU RAM further: reward.num_workers=2, smoke uses 2 dataloader workers and ref on GPU. Judge reward now has a per-sample `compute_score` (reward loop calls one sample at a time in a thread pool). Queue no longer exits on failure: skips the rest of QUEUE, stays up for IDLE_HOURS, then shuts down.

- 2026-11-03 (design note, top-k for GCA salience; not implemented yet): verl's vLLM server already returns per-call top-k heads (`response_topk_ids/log_probs` in extra_fields, enabled by `rollout.topk_log_probs`), but `tool_agent_loop` does not accumulate them across turns and `agent_loop.py` raises for num_turns>2. Two options: (A) patch the tool loop to append heads per assistant turn + dummy heads for tool tokens, relax the check; risk: token re-alignment in `continuous_token_builder`, and vLLM `max_logprobs` defaults to 20 < M=32 (engine arg needed). (B) compute top-32 from the actor's own forward during old-log-prob recompute (true pi_old, no alignment issue); risk: patching the actor/engine code. Decide after the smoke run. Until then GCA uses constant salience c=c_max, which is itself a useful ablation (paper App. E.6 reports insensitivity to K, M).
